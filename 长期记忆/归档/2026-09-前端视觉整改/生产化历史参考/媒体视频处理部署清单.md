# 媒体视频处理部署清单

> 状态：`[IN_PROGRESS]` 代码与迁移已就绪，等待生产基础设施和真实授权视频验收。
> 适用应用：`ai音乐/ai-music-app`

## 已实现流程

1. 运营后台上传 MP4/WebM 后，原件继续以私有对象保存，媒体记录进入 `PENDING`，并创建 `MediaProcessingJob`。
2. 受 `MEDIA_WORKER_TOKEN` 保护的 `POST /api/admin/media/process-next` 领取一个任务，使用 FFmpeg 输出兼容性 MP4 与 JPG 海报；两者写入独立 `media/processed/{assetId}/...` 对象前缀。
3. 成功后，公开 `/api/media/:assetId` 自动改为代理兼容 MP4；转码尚未完成时仍可受控代理原始视频，避免已经发布的素材出现无内容状态。
4. 失败会记录脱敏错误状态，运营人员可在媒体库点击“重新处理视频”。处理状态、重试和上传均写入审计。
5. 运营人员可为视频上传 UTF-8 WebVTT 字幕并指定语言；字幕对象独立私有保存，公开视频播放器通过 `/api/media/:assetId/captions` 受控读取，媒体元数据版本会记录字幕对象与语言。

## 部署前必须完成

- 执行 `npx prisma migrate deploy`，包含 `20260902100000_media_processing`。
- 在 Worker 容器或受控任务运行环境安装 FFmpeg，并设置 `FFMPEG_PATH`（未设置时 Windows 尝试 `ffmpeg.exe`，其他环境尝试 `ffmpeg`）。
- 设置高熵 `MEDIA_WORKER_TOKEN`；定时任务使用 `Authorization: Bearer <MEDIA_WORKER_TOKEN>` 调用上述处理端点，每次只领取一个任务，可按队列长度并行但必须限制并发。
- 配置私有对象存储（生产使用 `STORAGE_DRIVER=OSS` 与最小 RAM 权限）；Worker 需要读取原始媒体及写入 `media/processed/`，公开 Web 应用只通过受控媒体路由读取播放源。
- 按业务时长设置 `MEDIA_PROCESSING_TIMEOUT_MS`（30 秒至 30 分钟，默认 10 分钟）；上传上限继续由 `MEDIA_VIDEO_UPLOAD_MAX_BYTES` 控制。
- 上传并验证一段已获授权的 MP4 和一段 WebM：检查转码状态、海报对象、桌面/移动播放、失败重试、下线立即不可访问和审计记录。
- 上传一份真实 WebVTT 字幕，验证前台播放器字幕开关、语言标识、下线后字幕返回不可用，以及字幕更新后的媒体版本记录。

## 尚未宣称完成的能力

- 当前发布播放源是兼容 MP4，不是 HLS 自适应码率流；高并发或长视频上线前需接入分片转码、CDN 和受控 HLS 清单/分片授权。
- 已预留人工上传的 WebVTT 字幕能力；未生成自动转写。字幕内容生产、无障碍说明、人工审校和多尺寸码率策略仍需要在内容团队与媒体服务选型后实施。
- 浏览器端不能绝对阻止录屏或高级抓取；公开媒体仅适用于确认可公开展示且已完成授权核验的素材。
