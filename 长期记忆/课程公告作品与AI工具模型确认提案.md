# 课程公告、作品归属与 AI 工具目录模型确认提案

> 状态：`[CONFIRMED / IMPLEMENTED-LOCAL]` 项目负责人已于 2026-09-02 确认本提案的三项最小范围；模型、受控迁移、服务端权限、运营页面与学习页已实施并完成本地验证。真实管理员和学员账户的写入验收仍待继续。
> 适用应用：`ai音乐/ai-music-app`

## 1. 需要确认的目标

当前项目已具备课程、课时、报名、作品和课程工具绑定，但缺少三项独立的业务实体：

1. 学员可见、可审计的课程公告。
2. 作品与课程任务之间可追溯的归属关系。
3. 可由运营后台维护的 AI 工具展示与全局启停目录。

下述方案保留已经确认的边界：个人作品始终归个人账户；课程工具仍走同一网关；任何课程访问、课件访问、点数与匿名试用判断仍由服务端强制执行。

## 2. `CourseAnnouncement`：课程公告

建议字段：

| 字段 | 含义 |
|---|---|
| `id`、`courseId` | 公告与所属课程 |
| `title`、`content` | 公告标题与正文 |
| `publishStatus` | `DRAFT`、`REVIEW`、`PUBLISHED`、`ARCHIVED` |
| `publishAt`、`publishedAt` | 可选定时发布时间与实际发布时间 |
| `sortOrder` | 同一课程内展示顺序 |
| `createdBy`、`updatedBy`、`createdAt`、`updatedAt` | 运营与审计追溯 |

权限与行为：

- 仅运营管理员可创建、编辑、送审、发布、下线和恢复公告。
- 学员端只读取本人有效报名课程的已发布、且已到达 `publishAt` 的公告。
- 无有效报名、报名过期、账号停用或课程未发布时一律不返回公告。
- 公告的每次发布、下线、恢复均写入审计；是否需要不可变版本快照可沿用现有 `ContentRevision` 模式实施。

## 3. `WorkCourseContext`：课程任务作品归属

建议字段：

| 字段 | 含义 |
|---|---|
| `id`、`workId` | 关联既有个人作品 |
| `courseId`、`lessonId` | 创建时的课程和可选课时上下文 |
| `enrollmentId` | 证明当时使用的有效报名 |
| `contextType` | `COURSE_TOOL`、`LESSON_TASK`、`MANUAL_LINK` |
| `createdAt` | 归属记录创建时间 |

权限与行为：

- 作品的所有权、下载、删除和存储配额仍由现有 `Work.accountId` 决定；此表不复制作品文件、不转移所有权。
- 仅当个人账户在创建时有有效报名、课程/课时已发布且工具绑定有效时，网关或服务端可创建 `COURSE_TOOL` / `LESSON_TASK` 归属。
- 后续报名过期不删除历史归属，但学习页不应把过期课程重新开放。
- 不允许客户端仅凭 `courseId` / `lessonId` 写入归属；服务端需要重新校验报名和工具绑定。
- 默认一件作品可以保留一个创建来源；若项目负责人需要“一件作品可关联多门课程/多个任务”，需在实施前改为多对多并追加去重规则。

## 4. `AiTool`：运营后台工具目录

建议字段：

| 字段 | 含义 |
|---|---|
| `id`、`toolKey` | 工具稳定标识；首期只能取现有网关能力键（如 `image`、`code`、`music`、`vision` 等） |
| `name`、`description`、`category` | 公开目录和后台显示文案 |
| `routePath`、`sortOrder` | 已实现工具页面的稳定路径与排序 |
| `status`、`visibleToPublic` | 全局启停和是否展示于 `/tools` |
| `allowAnonymousTrial`、`dailyTrialLimit` | 是否允许匿名试用及默认每日上限 |
| `coverAssetId` | 后台可维护的工具卡封面媒体 |
| `createdBy`、`updatedBy`、时间字段 | 审计追溯 |

权限与行为：

- 首期不支持运营后台创建任意新供应商能力或任意新路由；只管理已经实现并经服务端白名单保护的工具键，避免后台配置绕过网关代码与供应商安全边界。
- `status` 为停用时，目录不展示、学校账号不可用、课程绑定不可新建；网关在供应商调用前拒绝。历史作品和审计不删除。
- `visibleToPublic=false` 只隐藏公开目录卡片，不等于授权。实际使用仍由账户权益、课程绑定、学校配置、点数和网关共同决定。
- `dailyTrialLimit` 默认使用已确认的每工具每日 5 次；任何改动都仍走 Redis、并发与成本保护，不能由前端直接决定。

## 5. 推荐实施顺序（确认后）

1. 新增 Prisma 模型、关系、索引与受控迁移；不回填或虚构课程公告、作品归属、工具内容。
2. 增加管理员 API、字段白名单、发布/启停策略、审计和自动化测试。
3. 增加后台管理页：公告、课程作品筛选、工具目录配置。
4. 增加学员课程页公告与课程作品区；更新 `/tools` 仅读取启用且可见的工具目录。
5. 将网关与课程绑定验证改为读取工具全局状态，同时保持原有权益、匿名试用、Redis 和点数检查。
6. 使用真实数据库、管理员、个人学员、学校账号、Redis 与私有 OSS 完成端到端验收。

## 6. 需要项目负责人确认的最小范围

请确认以下三项是否按本提案实施：

1. 新增 `CourseAnnouncement`，并只向有效报名学员展示已发布公告。
2. 新增 `WorkCourseContext`，作品仍归个人账户；默认一件作品只保留一个创建来源。
3. 新增 `AiTool`，仅管理现有服务端白名单工具的展示与全局启停，不允许后台创建任意新供应商工具或绕过网关。

已确认并实施的范围：

- `CourseAnnouncement` 仅由管理员维护；学员端只读取自身有效报名课程中已发布且到达发布时间的公告。
- `WorkCourseContext` 保持作品由个人账户所有；每件作品仅保留一个创建来源，关联写入时重新校验有效报名和已发布课程/课时。
- `AiTool` 仅管理既有网关白名单工具的展示、启停与匿名试用策略；网关在供应商调用前读取全局状态并拒绝不可用工具。
